# 站点积分台 · Site Points Hub

**通用多站点签到与积分管理 Hub**：把分散在各个网站里的账户余额、每日签到与运行记录收进一处 —— 自托管、单实例、单管理员，凭据加密落盘。附带一个浏览器扩展，可以把已登录的 New API / One API 站点一键收编，免去手工复制 Cookie 和用户 ID。

## 兼容范围（务必先读）

本 Hub 的能力边界是诚实的，不夸大兼容：

- ✅ **原生支持：New API / One API 及其兼容分支面板**。这类面板有一套标准的账号接口（`/api/user/self` 读余额、`/api/user/checkin` 签到、`Cookie + New-Api-User` 请求头鉴权），本项目原生实现，开箱即用，浏览器扩展也只针对这套接口做自动识别与导入。
- ⚙️ **适配支持：其他任何网站**。前提是它**存在可调用的余额 / 签到 HTTP 接口**，并且你按[第三方站点适配指南](#第三方站点适配指南)抓包确认接口路径与响应字段后，用「自定义 JSON API」完成适配。适配本身只是填几个字段，但**必须由你确认接口真实可用**。
- ❌ **不支持**：没有可调用接口、只能网页点击、或依赖验证码 / Turnstile / 站点风控才能操作的站点。本项目不会模拟浏览器行为去绕过任何站点的防护（服务器浏览器仅用于在站点自身规则允许的范围内续期登录态）。

一句话：**New API / One API 是一等公民；其他站点能接入与否，取决于它有没有可调用的接口，而不是本项目承诺。**

## 功能介绍

- **余额轮询**：按标签批量轮询，间隔可配（`POLL_INTERVAL_MINUTES`），卡片实时显示余额与最近状态。
- **每日定时签到**：到点自动为启用轮询的站点签到（`AUTO_CHECKIN_HOUR`），识别"已签到 / 成功 / 失败"，不影响手动签到。
- **运行日志**：网关、轮询、签到三类执行记录，可按类型、结果、站点筛选。
- **标签体系**：自由打标签，只有点亮参与轮询的标签才会被定时任务与统一网关使用；卡片可拖动排序。
- **浏览器扩展一键导入**：已登录的 New API / One API 站点自动识别面板类型、登录态、数字用户 ID、余额与签到接口，勾选即导入（见[浏览器扩展使用](#浏览器扩展使用)）。
- **统一网关**：OpenAI 兼容的 `/v1` 入口，按站点顺序自动切换真实模型，含调用统计（Token 用量、成功率、耗时排行）。
- **Bearer 自动续期**：短期 Token 站点可配置刷新接口 + 轮换 Cookie，401 自动刷新重试；绑定登录 IP 的站点可选用服务器浏览器续期。
- **凭据加密**：所有 Cookie / Bearer / API Key 以 AES-256-GCM 加密存储，密钥来自 `APP_SECRET`。
- **公开邀请页**：`/invites.html` 只展示管理员为各站点填写的显示名称、标签与邀请链接，不公开余额、凭据或模型配置。

## 安全边界

- **只允许 HTTPS 公网地址**（本地开发例外），并主动解析 DNS 阻止内网地址，避免被当成 SSRF 跳板。
- **导入 Token 最小权限**：后台生成的浏览器导入 Token 只能调用 `/api/import/*`，不能登录后台、不能读取已保存凭据与 API Key、不能访问统一网关；服务端只保存其 SHA-256 哈希，可随时重新生成或吊销。
- **扩展隐私红线**：不读浏览历史、不扫未打开的站点、不读其他域 Cookie；API 探测在目标页面内同源发起，Cookie 只在你确认导入的那一刻读取并只发给你自己的积分台。
- **扫描探测无副作用**：绝不 POST 签到接口，签到能力探测只使用无副作用的 GET / 状态字段识别。
- **验证失败不入库**：浏览器导入的凭据会先真实调用一次余额接口，验证不过就不保存，绝不留下"看似成功"的坏账号。
- **单管理员单实例设计**，适合个人使用；仅接入你拥有或明确获授权的账户。

## 快速部署

### 本地运行

需要 Node.js 20+。

```powershell
$env:ADMIN_PASSWORD="换成你的管理密码"
$env:APP_SECRET="换成至少32位随机字符串"
$env:GATEWAY_API_KEY="换成客户端访问网关时使用的总Key"
npm install
npm start
```

打开 `http://localhost:8080`。修改 `APP_SECRET` 后，已保存凭据将无法解密。

### Zeabur（Docker）

1. 推到 GitHub，在 Zeabur 新建项目并选择仓库，根目录 `Dockerfile` 会被自动识别。
2. 服务变量：

   | 变量 | 说明 |
   | --- | --- |
   | `ADMIN_PASSWORD` | 控制台登录密码 |
   | `APP_SECRET` | ≥32 位随机字符串，凭据加密密钥 |
   | `GATEWAY_API_KEY` | 客户端访问统一网关的总 Key |
   | `POLL_INTERVAL_MINUTES` | 轮询间隔，默认 `30` |
   | `AUTO_CHECKIN_HOUR` | 每日签到小时，默认 `8` |
   | `TZ` | 时区，建议 `Asia/Shanghai` |

3. **添加持久卷，挂载路径 `/data`**，否则重新部署后账户、历史与浏览器登录状态全部丢失。
4. Networking 绑定域名；健康检查 `https://<域名>/health`。

轮询由进程内定时器完成，不依赖平台 Cron；为避免重复签到请只运行一个副本。

## 浏览器扩展使用

扩展位于 [`browser-extension/`](browser-extension/)，Manifest V3，Chrome / Edge / Firefox 通用，详细说明见 [browser-extension/README.md](browser-extension/README.md)。

1. 后台「浏览器导入」面板 → **生成导入 Token**（只显示一次；重新生成会立即吊销旧 Token）。
2. 加载扩展（Chrome：`chrome://extensions` → 开发者模式 → 加载已解压的扩展程序），填入积分台地址与 Token。
3. 保持站点标签页打开 → **扫描当前站点 / 扫描所有已打开标签页**。扩展在页面内同源探测，识别 New API / One API 面板、登录态、用户 ID、余额与签到接口，按站点去重、并发受限。
4. 勾选 → **加入积分台**。缺用户 ID 的站点可当场补填；同一站点重复导入会更新登录态而不是重复建号。
5. 导入后不依赖浏览器继续打开 —— 服务器按现有定时逻辑自行签到与轮询。

只有 New API / One API 兼容面板能被自动识别导入；其他站点请走[适配指南](#第三方站点适配指南)手动接入。

## 第三方站点适配指南

非 New API / One API 站点使用「自定义 JSON API」类型接入。适配前先抓包（浏览器 F12 → Network）确认两件事：余额接口和签到接口是否真实存在、响应 JSON 的字段路径是什么。

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| 余额接口 `balancePath` | GET 余额的路径 | `/api/user/points` |
| 余额字段 `balanceField` | JSON 字段路径 | 响应 `{ "data": { "points": 120 } }` 填 `data.points` |
| 余额除数 `balanceDivisor` | 原始积分 ÷ 除数 = 显示值 | 积分按 0.01 元计填 `100` |
| 签到接口 `checkinPath` | 签到路径与请求方式 | `/api/checkin` + `POST` |
| 认证方式 `authType` | `Bearer Token` / `Cookie` / 自定义请求头 | 自定义头填 `headerName` |
| 刷新接口 `refreshPath` | 短期 Bearer 的续期接口 + `new_api_refresh` Cookie | 401 自动刷新并重试一次 |
| 续期方式 `refreshMode` | 站点绑定登录 IP 时选「服务器浏览器」 | 在卡片里远程登录一次 |

适配步骤：添加站点 → 面板类型选「自定义 JSON API」→ 填入上表字段与凭据 → 保存后点「刷新」验证余额读取 → 点「签到」验证签到接口。**如果抓包发现站点根本没有可调用的接口，那就是不支持，本项目不会替你点网页。**

各站接口格式差异很大；若你适配了新的站点类型并希望沉淀为开箱即用的模板，欢迎在上游讨论。

## 统一网关

在每个站点中填写上游 API Key，并从分类价格列表中选择一个模型后，客户端配置：

```text
Base URL: https://你的域名.zeabur.app/v1
API Key: 你设置的 GATEWAY_API_KEY
Model: xiaoju-auto（也可填写任意非空名称）
```

支持 `/v1/models`、`/v1/chat/completions`、`/v1/responses` 和 `/v1/embeddings`。只有属于已启用轮询标签、已填写上游 API Key 且已选定真实模型的站点会参与；任一上游返回非成功状态或发生网络错误时都会继续尝试下一个站点。

每次上游尝试都会写入「最近运行」，类型显示为「网关」，并记录实际模型和 HTTP 结果；不会保存请求正文或对话内容。左侧「调用统计」提供今日 / 本月 / 累计请求、成功率、Token 用量与站点 / 模型 / 失败原因排行；统计不读取对话内容，也不把积分换算为金额。

## 已知边界

- 某些站点 Cookie 会过期，需要重新更新或配置续期。
- 服务器浏览器无法保证绕过 Turnstile、机房 IP 限制或站点自身的风控；只应用于你有权登录的账户。
- 价格接口不可用时，模型仍会以「价格未知」显示并可正常选择与使用。
- 当前是单管理员、单实例设计，适合个人使用。
